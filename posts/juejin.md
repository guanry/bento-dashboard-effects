## 为什么不用 SortableJS / Muuri?

它们很优秀,但解决的是"列表拖拽排序"。我要的是:**不等大卡片、拖拽时其余卡片实时让位、松手吸附到最近有效格位**——满铺网格里有些落点在几何上就是无解的(比如把 2×1 的卡拖进正中间,剩余空间根本放不下其他卡),这类问题通用库不会替你处理。

于是自己写了引擎,核心只有三句话:

1. **卡片是网格容器里的绝对定位元素,位置用 `translate3d` 表达,动画全靠 CSS transition**
2. **JS 只做一件事:算出每张卡的目标矩形(x/y/w/h)**
3. **数据一变,浏览器自己动**

拖拽让位、松手吸附、就地放大、缩成缩略条、主题切换时卡片滑到新构图——全部是"改矩形"这一件事的不同应用。

## 几个值得讲的机制

### 1. 让位的"空位引力"

被挤的卡片找新家时,打分公式是:

```
score = 自身位移² + 2 × (到空位的距离)²
```

没有第二项,卡片会斜着挪一格而不是流向被拖走的空位,连锁让位会绕路;加上"同尺寸卡片直接换位"规则,拖走再拖回能**精确还原**。

### 2. 满铺网格的无解格位

4×3 全占满时,把 2×1 的卡拖到 (1,0),剩下 8 格放不下其余 10 格的卡——无解。引擎对每个期望落点按距离排序试解,第一个**合法**布局胜出。这就是"吸附到最近格位"的真正含义。

### 3. 滚动吸顶被滚动锚定打脸

做"滚动时收缩的头部"那天,采样发现 scrollTop 被浏览器悄悄拉回 0——Chrome 的 **scroll anchoring** 在检测到内容位移时会回滚滚动位置来"抵消"你刚做的收缩。修复只要一行:

```css
.scroll-container { overflow-anchor: none; }
```

### 4. 后台标签页会永久卡住 `<Transition mode="out-in">`

Vue 等 transitionend 才挂载新内容,而后台标签页的回调被无限推迟——面板停在旧数据上,状态却是对的,排查极其绕。稳健写法:`:key` 强制重渲染 + 纯 CSS 入场动画。

## 六套主题:换肤只是开始

主题系统三层:语义令牌覆盖层 → **主题感知布局**(`setGrid` 直接切网格规格,撞色主题的主卡构图、沉浸主题的 12×6 打破网格)→ **内容级变体**(图卡内容主题下,卡片渲染成照片卡和行程面板)。

切主题时所有卡片滑行到新构图——因为布局切换复用了同一套矩形过渡。
